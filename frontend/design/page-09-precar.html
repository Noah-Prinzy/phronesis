Seven new atoms, forty reused

New here: spec row, vehicle card, comparison table, price band, trend sparkline, budget slider, pro/con list. Everything else on these screens — buttons, chips, cards, tabs, search, rail, tab bar, the hologram, the avatar — is the post-car library unchanged.

That ratio is the whole argument for building components before pages. A second journey costs seven atoms instead of a second frontend.

No colour, on purpose

Nothing in the pre-car journey is critical or a warning, so red and amber never appear here. Price is expressed as a position on the monochrome ramp with ember marking where a car sits — and there is no green for “good deal”, consistent with removing green everywhere else.

This sharpens the rule instead of straining it: red and amber exist in Phronesis only where safety is at stake.

What gates this, and it is not the screens

Post-car generates its own data — the OBD reads codes, the user describes symptoms. Pre-car has no such source. Discover and Compare are only as good as a vehicle-spec and Ugandan market-price corpus that does not exist yet, and the regional comparison needs cross-border listing data maintained continuously, not scraped once.

Every number on these screens is invented. That is fine for a mockup and fatal in production, which is why Phase 3 should be gated on the data, not on the design.
